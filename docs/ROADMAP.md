# แนวทางพัฒนาต่อ

สิ่งที่ระบบยังทำไม่ได้ เรียงตามความคุ้มค่าต่อแรงที่ลง

---

## 1. บันทึก snapshot ความมั่งคั่งสุทธิรายเดือน ⭐ คุ้มที่สุด

ตอนนี้ Net Worth คำนวณสดจากค่าปัจจุบัน — เห็นแค่ "ตอนนี้เท่าไร" แต่ไม่เห็น "โตขึ้นเดือนละเท่าไร"

```sql
create table public.net_worth_snapshots (
  id         uuid primary key default gen_random_uuid(),
  user_id    uuid not null references auth.users(id) on delete cascade,
  captured_on date not null,
  total_asset     numeric(14,2) not null,
  total_liability numeric(14,2) not null,
  net_worth       numeric(14,2) not null,
  unique (user_id, captured_on)
);
```

เก็บทุกสิ้นเดือน แล้วทำกราฟเส้นย้อนหลังหลายปี — น่าจะเป็นตัวเลขที่สร้างแรงจูงใจได้ดีที่สุดในระบบ

## 2. รายการประจำ (recurring) แบบเติมอัตโนมัติ

ตาราง `recurring` มีอยู่แล้วใน schema แต่ยังไม่ได้ต่อ UI —
ตั้งครั้งเดียวว่า "ค่าที่พัก 5,000 ทุกเดือน" แล้วพอขึ้นปีใหม่ระบบเติมให้เลย
(ตอนนี้ใช้ปุ่ม "กรอกหลายเดือนรวดเดียว" แทนไปก่อนได้)

## 3. บันทึกรายการย่อยรายวัน

ตอนนี้กรอกเป็นยอดรวมรายเดือน ทำให้ตอบไม่ได้ว่า "ค่ากินเดือนนี้หมดไปกับอะไร"
เพิ่มตาราง `transactions` ที่ผูกกับ category + วันที่ แล้วให้ยอดรายเดือนคำนวณจากผลรวม
โดยยังกรอกยอดรวมตรง ๆ ได้เหมือนเดิมสำหรับคนที่ไม่อยากละเอียด

## 4. แจ้งเตือนให้มาอัปเดตข้อมูล

ระบบแบบนี้ตายเพราะคนลืมกรอก — ส่งอีเมลเตือนต้นเดือน (Supabase Edge Function + cron)
หรืออย่างน้อยแสดง badge "เดือนที่แล้วยังไม่ได้กรอก" บนหน้าภาพรวม

## 5. เทียบปีต่อปี

"ปีนี้เทียบปีที่แล้ว รายจ่ายหมวดไหนโตขึ้น" — ตอนนี้ต้องสลับปีไปมาดูเอง

## 6. โหมดจำลอง (what-if)

"ถ้าลดค่าใช้จ่ายฟุ่มเฟือยเดือนละ 3,000 จะไปถึงเป้าเร็วขึ้นกี่เดือน"
เลื่อน slider แล้วเห็นเส้นในหน้า "เส้นทางสู่เป้า" ขยับทันที
ฟังก์ชัน `milestone()` ใน `calc.js` เป็น pure function อยู่แล้ว ต่อยอดได้ไม่ยาก

## 7. รองรับเงินเฟ้อ

เป้าหมาย 1 ล้านในอีก 10 ปี ไม่เท่ากับ 1 ล้านวันนี้ — ถ้าเป้าหมายยาวเกิน 5 ปี
ควรมีตัวเลือกแสดงเป็นมูลค่าปัจจุบันด้วย

## 8. แชร์ให้คู่ชีวิต/ที่ปรึกษาแบบอ่านอย่างเดียว

เพิ่มตาราง `shares (owner_id, viewer_id)` แล้วขยาย policy:

```sql
using (
  auth.uid() = user_id
  or exists (select 1 from shares s
             where s.owner_id = user_id and s.viewer_id = auth.uid())
)
```

โครงสร้าง RLS ปัจจุบันรองรับการต่อยอดนี้ได้เลย โดยไม่ต้องแก้โค้ดหน้าเว็บ

## 9. รองรับหลายสกุลเงิน

คอลัมน์ `currency` มีอยู่ใน `profiles` แล้ว แต่ยังไม่ได้ใช้จริง —
ตอนนี้ทุกอย่าง hardcode เป็นบาท

# หลักการวางแผนการเงินที่ระบบยึดถือ

เกณฑ์ที่ใช้ตั้งค่าเตือนและตัวชี้วัดต่าง ๆ ในระบบ

| ตัวชี้วัด | เกณฑ์ | เหตุผล |
|---|---|---|
| **อัตราการออม** | ≥ 20% ของรายรับ | เกณฑ์มาตรฐานที่ใช้กันทั่วไป ต่ำกว่านี้แทบไม่มีทางสร้างความมั่งคั่งทัน |
| **เงินสำรองฉุกเฉิน** | 6 เท่าของรายจ่ายเฉลี่ยต่อเดือน | ครอบคลุมช่วงตกงาน/เจ็บป่วยโดยไม่ต้องขายสินทรัพย์ลงทุนตอนราคาตก |
| **หนี้สินต่อสินทรัพย์** | < 50% | เกินกว่านี้ความยืดหยุ่นทางการเงินจะต่ำมาก |
| **รายจ่ายต่อรายรับ** | < 70% | เหลือช่องว่างให้ออมได้จริงหลังหักภาระประจำ |

**ลำดับความสำคัญที่แนะนำ**

1. เงินสำรองฉุกเฉินให้ครบ 6 เดือนก่อน — ก่อนจะไปคิดเรื่องลงทุน
2. ปิดหนี้ดอกเบี้ยสูง (บัตรเครดิต สินเชื่อส่วนบุคคล) — ไม่มีการลงทุนไหนชนะดอกเบี้ย 16–25% ได้แน่นอน
3. ใช้สิทธิ์ลดหย่อนภาษีให้เต็มฐานภาษีสูงสุดของตัวเอง — เป็น "ผลตอบแทนที่การันตี" เท่ากับอัตราภาษีขั้นสูงสุด
4. ลงทุนระยะยาวส่วนที่เหลือ
5. **หนี้ดอกเบี้ยต่ำ (เช่น กยศ. ~1%) ไม่ต้องรีบโปะ** — เอาเงินไปลงทุนได้ผลตอบแทนสูงกว่า

**ข้อควรระวังเรื่องภาษี**

หน้าแผนภาษีคำนวณ**ประมาณการ** ตั้งอยู่บนสมมติฐานเงินได้ประเภท 40(1)(2)
หักค่าใช้จ่ายเหมา 50% (เพดาน 100,000) และลดหย่อนส่วนตัว 60,000

ถ้ามีรายได้ประเภทอื่น (เช่น 40(8) เงินได้จากธุรกิจ) วิธีหักค่าใช้จ่ายจะต่างออกไป
และเพดานสิทธิ์ลดหย่อนของกองทุนแต่ละประเภทเปลี่ยนได้ทุกปี — ตรวจสอบกับกรมสรรพากรก่อนยื่นจริง
